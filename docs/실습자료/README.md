# 설치 후 확인하는 두 가지 실습

강의 기본값은 바탕화면의 `Output`에 `00_올해안내문.odt`, `01_올해공문.odt`처럼 결과를 바로 저장합니다. 업무별 하위폴더와 받은자료는 만들지 않으며 원본은 제자리에 둡니다. 기존 결과·선택 경로는 보존합니다. 연구회 신청서의 별도 제공 자료를 사용하는 시연은 [연구회 시연 명령](연구회시연.md)을 사용합니다.

학교·개인정보가 없는 가상 연수자료입니다. 연수는 하네스 설치·문서 2개 편집 확인 후, 같은 작업을 반복할 스킬 제작으로 이어집니다. **입력 3개만** 받습니다: 작년 안내문 ODT, 기존 공문 ODT, 공통 근거 Markdown. 저장소의 Code → Download ZIP으로 받은 폴더에 함께 들어 있습니다.

## 1. 작년 자료를 올해 자료로
설치한 프로젝트에서 입력자료를 지정하고 다음을 요청합니다.

> `docs/실습자료/01_작년안내문.odt`를 기준본으로 열고 `docs/실습자료/03_올해공통근거.md`에 따라 올해 안내문으로 수정해 줘. 원본은 제자리에 두고 수정하지 마. 학년도·행사일·장소·신청 마감·발행일만 바꾸고 다른 내용과 서식을 유지해 줘. 결과는 기본 Output에 번호가 붙은 새 ODT로 저장하고 변경 전후와 저장 위치를 알려 줘.

확인: 2026학년도 / 11월 12일 / 시청각실 / 신청 11월 5일 / 발행 10월 29일. 시간·대상·준비물·무료·인사말은 그대로여야 합니다.

## 2. 공문을 올해 근거에 맞게

> `docs/실습자료/02_기존공문.odt`를 기준본으로 열고 같은 공통 근거자료에 따라 올해 변경 기안 본문으로 수정해 줘. 원본은 제자리에 두고 수정하지 마. 관련 공문의 번호·시행일과 학년도·행사일·장소·신청 마감을 바꾸고, 올해 근거가 없는 예산은 `확인 필요`로 표시해 줘. 나머지 문장·항목 순서·서식은 유지해 줘. 새 등록번호·결재일·서명은 만들지 마. 결과 ODT를 기본 Output에 번호 파일로 저장하고, 제목·수신과 미확정 사항을 채팅으로 알려 줘.

확인: 관련 별빛학교-2345(2026. 10. 19.), 예산 확인 필요. 20명·운영 원칙·기존 방법 문장은 그대로. 없는 붙임을 첨부했다고 하지 않아야 합니다.

## 모델과 성공 판정
Luna로 먼저 작은 작업 1개씩 요청하고 원본·결과를 직접 비교합니다. 이번 제작에서 ODF API로 두 예제의 수정·재열기·원본 해시·정확한 문구·저장 서식을 검사했습니다. **이것은 Luna 모델의 작업 성공률이나 한컴 화면 검증을 뜻하지 않습니다.** 실제 모델 테스트 범위는 아래의 「Luna 실행 확인 범위」에서 구분합니다.

## 실패했을 때 시스템을 고치는 순서
1. 오류 메시지·사용 파일·기대 결과를 남깁니다. 원본을 덮어썼으면 즉시 중단하고 보관본에서 복구합니다.
2. 설치 실패는 모델을 바꾸기 전에 `INSTALL.md`와 `Install.ps1 -CheckOnly` 결과를 확인합니다. 경로는 `.agent/index/delivery-system.json`, 런타임은 설치 보고서로 확인합니다.
3. 파일을 읽지 못하면 해당 형식의 실행기와 경로를 점검합니다. ODT에 `--form paste`를 무조건 쓰지 않습니다. 이 배포본 CLI는 `general/internal`만 허용하며, 기존 ODT는 재생성하지 않고 ODF API로 사본의 지정 텍스트를 수정합니다.
4. 날짜·근거를 잘못 판단하면 `AGENTS.md`에는 '선택한 기준본을 먼저 읽고, 현재 근거가 있는 값만 변경하며 미확정 값은 추정하지 않는다'는 공통 규칙을 짧게 둡니다. 특정 예제의 날짜·학교명은 공통 규칙에 넣지 않습니다.
5. 반복되는 문서별 문제는 `.agents/skills/`의 해당 스킬 또는 `.agent/shared/`의 실행기에서 수정합니다. 수정 전후에 같은 실패 입력과 정상 입력을 모두 다시 실행합니다. 생성기를 고쳐 기존 문서 전체를 다시 만들지 않습니다.
6. 같은 입력에서 Luna가 계속 판단을 놓치면 더 높은 모델로 원인을 분석하고 테스트 가능한 작은 절차로 바꾼 뒤 Luna로 재검증합니다. 단순히 높은 모델에서 성공했다고 Luna도 성공했다고 쓰지 않습니다.

자료는 실제 전자결재 연결, 직인·결재 처리, HWPX 서식 보존을 검증하지 않습니다. 공문 ODT는 본문 실습이며 제목/수신은 기안기 입력 칸과 구분합니다.


## 나만의 스킬 만들기 — 실습 2

앞의 문서 두 개 수정은 **실습 1: 하네스 설치·사용**입니다. **실습 2**에서는 행사 준비 내용을 채팅에서 분석하는 공통 예제로 스킬을 만든 뒤, 세 주제 중 자신의 반복 업무를 고릅니다. 이 실습의 결과는 채팅으로만 제시하며 문서·표·텍스트 파일을 작성하거나 업무폴더에 게시하지 않습니다. 파일 작성으로 확장하려면 기존 초안·양식을 먼저 지정하고 읽어야 합니다.

| 주제 | 입력 | 결과 | 확인 기준 |
|---|---|---|---|
| 행사 준비 분석 | 행사 메모 | 채팅의 준비물·담당·기한 표 | 없는 담당·기한은 확인 필요 |
| 안내문 점검 | 안내문 초안 | 채팅의 누락·모순 점검 목록 | 날짜·장소·대상·준비물 확인 |
| 공문 변경점 점검 | 이전 공문 + 올해 근거 | 채팅의 변경점·확인 필요 목록 | 근거 없는 수치 생성 금지 |

프로젝트 채팅에서 **`$skill-creator`를 명시해 호출**합니다. 해당 스킬이 보이지 않으면 사용 가능 여부를 먼저 확인합니다.

```text
$skill-creator
행사 메모를 분석해 채팅에서 준비물·담당·기한을 확인하는 스킬을 만들어줘.
이 프로젝트의 .agents/skills/event-checklist/에 저장해줘.
입력은 행사 메모, 결과는 채팅의 준비물·담당·기한 표와 확인 필요 목록이야.
자료에 없는 담당·기한은 만들지 말고 '확인 필요'로 표시해.
입력 파일은 제자리에 보존하고 수정하거나 별도 받은자료 사본을 만들지 마.
업무 결과 파일은 작성하거나 게시하지 말고 채팅으로만 분석해.
추후 파일 작성 요청은 기존 초안·양식을 먼저 지정받아 읽는 별도 문서 작업으로 처리해.
특정 학교명·날짜를 규칙에 고정하지 마.
```

1. `SKILL.md`의 이름·적용 상황·입력·보존 규칙과 채팅 분석 범위를 읽습니다. 스킬 파일 제작과 업무 결과 파일 작성을 구분합니다.
2. 새 채팅에서 `$event-checklist`를 호출하고 `docs/실습자료/03_올해공통근거.md`를 입력으로 지정해 채팅 분석만 요청합니다.
3. 준비물은 개인 노트북·충전기여야 하며, 준비물별 담당·기한은 근거가 없으므로 확인 필요입니다. 행사일이나 신청 마감을 준비물 기한으로 추정하지 않습니다.
4. 공통 근거의 **사본**에서 날짜·장소·준비물을 다른 가상 값으로 바꿔 다시 실행합니다. 첫 입력의 값이 남지 않는지 확인하고 실패한 규칙만 고칩니다.
## Luna 실행 확인 범위

다음은 Output 기본값 적용 전의 과거 실행 기록입니다. 2026-10-20 **gpt-6-luna / xhigh 완료 실행 1회**에서 당시 두 요청으로 안내문·공문을 수정하고 바탕화면의 `교사업무/연수실습 업무`에 결과를 저장했습니다. 세션의 시작부터 완료까지 약 **8분 28초**(508.47초)가 걸렸습니다. 내용 검사 23개를 통과했고, 안내문 5곳·공문 6곳의 요청된 텍스트 치환 외에 `content.xml`이 그대로이며 나머지 ODT 내부 파일도 바이트 단위로 동일함을 확인했습니다. 원본·보관 사본·게시 결과의 해시를 확인했으며 상위 검토자의 내용 수정은 없었습니다. 중간에 잘못 지정한 dry-run 영수증 경로는 실행 안에서 스스로 바로잡았습니다. 공통 읽기 도구의 별도 복구 1회가 있었으나 이 ODT 작업은 해당 도구를 사용하지 않았습니다. 이 시간은 앞서 중단된 실행이나 전체 하네스의 새 PC 설치 시간을 포함하지 않으며, 반복 실행 성공률·한컴 화면의 시각 검증·새 PC 설치 성공을 보장하지 않습니다.

2026-10-20 실행은 고정된 두 요청을 하위 에이전트에 전달한 시험이며, 수강생의 사용자 화면 설정과 실행 조건이 같다고 확인한 것은 아닙니다. 앞선 2026-10-19 **gpt-6-luna / medium 독립 실행 1회**에서도 두 예제의 내용·문서 구조·서식 XML 검사를 통과했습니다. 당시 임시 저장 경로 접근 오류는 결과 폴더 안에서 재시도했습니다. 각 수강생은 자신의 환경에서 결과 파일을 열어 확인합니다.

이전 Markdown 예제는 `legacy/`에 보관되어 있습니다. 현재 연수에서는 위 입력 3개만 사용합니다.
