# 구조와 개인화

이 배포본은 실제 업무 하네스의 공통 구조를 유지하고, 한 교사의 개인 경로와 담당 과목에 묶인 설정을 제거한 강의용 완성본입니다. 강의에서는 규칙의 위치와 개인 설정의 경계를 이해한 뒤 자신의 업무에 맞춥니다.

기능 수정과 합성 검사는 `teacher-harness-test`에서 진행하고, 확인한 변경을 `teacher-harness-release`에 반영합니다. 강의 배포본의 초기 업무·받은자료 경로는 실제 바탕화면의 `교사업무`, `받은자료`입니다. 번호 없이 업무명으로 저장하며 기존 선택 경로는 보존합니다. 테스트 중 원본 학교자료를 변경하지 않습니다.

## 공통으로 남긴 판단 원칙

- 사용자가 제시한 업무흐름·결과·완료 기준을 먼저 적용하고, 반복 입력이나 재작업을 줄일 구체적인 개선안을 제안합니다.
- 이미 선택한 업무와 유효한 자료를 재사용하고, 판단에 필요한 누락만 확인합니다.
- 사용자 지정 순서, 이전 관행, 현재 근거를 구분합니다. 전년도 양식과 파일명으로 올해의 일정·대상·결재 권한을 추정하지 않습니다.
- 현재본을 기준으로 요청 범위만 바꾸고 사람의 수정과 무관한 내용·서식을 보존합니다.
- 문서·표·텍스트 문안은 사용자 지정 초안/양식, 등록된 현재본, 명시적으로 선택한 이전 문서 순으로 먼저 열어보고 현재 근거로 필요한 내용만 채웁니다. 완료된 이전 문서도 기존 구조의 기준으로 쓸 수 있습니다. 기준본 부재·읽기 실패·모호한 선택이면 관련 작성을 멈추고 사용자에게 요청합니다. 새 양식을 만드는 방식으로 대신하지 않습니다.
- 사용자 제공 파일은 설정된 받은자료에 원본 사본을 자동 보관합니다. 접근할 수 없는 첨부는 저장했다고 말하지 않고 접근 가능한 경로를 요청합니다.
- 같은 반복 업무로 연결된 회차에 확정한 방법만 공유합니다. 특정 회차의 명단·일정·예외는 그 회차에 둡니다.
- 공통 도구와 지침은 하네스에, 실제 업무자료·작업본·수정 이력은 업무폴더에 둡니다.
- 문서의 완료 근거와 실제 결재·제출·통지 완료를 구분합니다. 검사 결과와 미확정 사항을 채팅으로 보고합니다.
- 독립된 작업은 병렬로 처리하되 현재본 게시와 설정 변경처럼 순서가 있는 작업은 의존관계를 지킵니다.

## 규칙과 실행의 위치

| 위치 | 맡는 역할 | 변경 시점 |
|---|---|---|
| `AGENTS.md` | 매 작업에 필요한 짧은 공통 원칙 | 공통 행동 기준을 바꿀 때 |
| `.agents/skills/work-planning/` | 업무 분류·순서·반복 처리 설계 | 업무 설계 방법을 바꿀 때 |
| `.agents/skills/hwpx-workspace-delivery/` | 자료 선택·현재본·접수·게시·검증 범위 | 공통 문서 처리 절차를 바꿀 때 |
| `.agents/skills/workspace-maintenance/` | 지침·코드·설정의 유지보수 | 명시적 유지보수 요청 때 |
| `.agents/skills/official-odt-draft/`, `evidence-fill-check/` | 프로젝트에서 전문 처리 지침을 찾는 진입점 | 전문 절차 연결이 바뀔 때 |
| `.agent/shared/` | 공통 실행 코드·검증·빈 양식·전문 지침 정본 | 영향받는 합성 검사와 함께 |
| `.agent/index/` | 이 컴퓨터의 업무 경로와 실행 환경 | 설치·이동·연결 변경 때 |
| 업무폴더의 `.ai/` | 선택 원본·내부 작업본·수정 이력·업무 예외 | 실제 업무 작업 중 |
| 연간 묶음의 `.ai/work-groups/` | 연결된 회차의 분류·선택 자료·확정 방법 | 해당 업무의 합의가 바뀔 때 |

원본 공통 실행기의 상대경로와 전문 지침 정본을 유지합니다. 프로젝트 스킬 진입점이 전문 지침으로 연결하므로 개인 스킬 폴더에 같은 스킬을 중복 등록할 필요가 없습니다.

## 개인화에서 제거한 것

개인별 업무·공문 수신 절대경로, 담당 과목과 업무에 묶인 고정 번호 매핑, 특정 개인업무 사례를 기본 규칙에서 제거했습니다. 업무 분류의 의미는 교사가 정하고 해당 업무 묶음에서 재사용합니다.

기존 결과물·학교 업무자료·설치 캐시·빌드 산출물·설치된 바이너리·개인 환경 설정 사본·과거 알림 기록은 배포하지 않습니다. 공통 실행 코드와 검증 코드, 빈 ODT 양식은 보존합니다.

빈 assets를 포함한 것은 자동 기본 양식을 정한 것이 아닙니다. 사용자가 선택해야 기준본으로 사용할 수 있습니다. ‘자료 없이 시작’, ‘새 초안’, ‘최종본’ 요청도 초안/양식 확인을 생략하지 않습니다. 질문·분석·업무계획 논의에는 양식을 요구하지 않습니다.

원본에서 이어받은 보수적인 내용·서식·시각 검사 범위는 실행기의 검증 계약과 연결된 공통 정책입니다. 문서 지침만 삭제해 게이트를 우회하지 않습니다. 다른 정책으로 바꾸려면 관련 지침과 실행기, 범위 검사를 함께 변경합니다.

## 교사가 자신의 환경에 맞출 것

1. `Setup.ps1`으로 업무·받은자료 경로와 필요한 런타임을 설정합니다.
2. 실제 담당 업무의 흐름과 기존 초안/양식, 필요한 현재 근거를 지정합니다. 모든 업무에 세 종류의 자료를 요구할 필요는 없습니다.
3. 분류번호와 반복 업무 연결을 정합니다. 새 학년도에는 새 흐름과 자료를 확인합니다.
4. 특정 업무에만 적용할 예외는 업무 기록에 둡니다. 매번 필요한 원칙만 공통 지침으로 올립니다.
5. 새로 만든 규칙은 가상의 입력으로 대표 요청을 확인하고, 실제 업무에서 필요한 부분만 적용합니다.

## 강의에서 확인할 흐름

완성본 폴더를 연 뒤 `AGENTS.md`의 한 원칙이 어떤 스킬과 도구로 이어지는지 따라갑니다. 예를 들어 '현재본과 요청 밖 내용을 보존한다'는 문서 스킬의 후속 수정, 내부 수정 이력, 게시 검사로 연결됩니다.

가상 행사 업무를 예로 들 수 있습니다. 교사가 만든 짧은 업무흐름, 기존 운영계획 또는 양식, 현재 일정자료를 제공합니다. 제공자료가 받은자료에 원본 사본으로 보관된 것을 확인하고, 업무 분류를 정한 뒤 기존 문서를 열어 필요한 내용만 채웁니다. 완료된 이전 계획을 선택한 경우에도 현재 일정·대상을 새 근거로 확인합니다. 초안/양식을 주지 않은 요청에서는 관련 작성을 멈추고 필요한 자료를 요청하는지도 확인합니다. 일정 한 항목을 후속 수정하면서 현재본 이름과 무관한 내용·배치가 유지되는지 확인합니다. 서식 정리와 시각 검사가 필요한 요청을 추가하면 해당 범위가 따로 기록되는지도 확인합니다.

마지막에는 반복 업무의 다음 회차를 연결해 확정한 처리 방법은 재사용하되 첫 회차의 일정·대상은 자동 상속하지 않는 것을 확인합니다. 실습의 목표는 많은 규칙을 추가하는 일이 아니라, 한 규칙을 어느 위치에서 관리하고 어떤 근거로 결과를 확인할지 설명하는 것입니다.

이 문서는 완성본의 구조 해설입니다. 실제 실행 조건과 설치 상태는 [INSTALL.md](../INSTALL.md)에 따라 컴퓨터별로 확인합니다.
