# 교사용 업무 하네스 — 배포용 완성본

교사가 제시한 업무흐름과 기존 초안·양식을 먼저 열어보고, 현재 근거로 필요한 내용만 채우며 현재본과 수정 이력을 보존하는 작업공간입니다. 원본의 공통 도구와 검증 절차를 유지하면서 특정 교사의 경로·과목·개인업무 분류를 제거했습니다.

`teacher-harness-test`에서 기능을 수정하고 합성 자료로 확인한 뒤 `teacher-harness-release` 배포용 폴더에 반영합니다. 강의에서는 검증한 배포본을 열어 각 부분의 역할을 확인하고, 자신의 업무 경로와 처리 기준을 설정합니다. 스크립트를 처음부터 작성할 필요는 없습니다.

## 처음 시작하기

GitHub에서 받으려면 [저장소](https://github.com/ray-math/teacher-harness-release)의 **Code → Download ZIP**을 선택하거나 [최신 배포본 ZIP 다운로드](https://github.com/ray-math/teacher-harness-release/archive/refs/heads/main.zip)를 누릅니다. ZIP 전체를 자신의 컴퓨터에 압축 해제한 뒤, `AGENTS.md`, `Install.ps1`, 숨김 폴더 `.agent`, `.agents`가 함께 있는 폴더를 Codex 프로젝트로 엽니다. 프로젝트 채팅에서 **“설치해줘”**라고 요청하면 됩니다. 공유 폴더로 전달받았다면 아래와 같이 폴더 전체를 복사해 시작할 수 있습니다.

1. 공유할 때는 `.agent/private/`와 개인 업무자료·설치 캐시를 제외한 배포 폴더 전체를 전달합니다. 받는 사람은 공유된 폴더 전체를 자신의 컴퓨터에 복사하고, 숨김 폴더 `.agent`, `.agents`까지 유지한 채 Codex에서 복사한 폴더를 프로젝트로 엽니다. 스킬을 따로 설치하거나 전역 개인 스킬 폴더로 복사할 필요가 없습니다.
2. 프로젝트 채팅에서 **“설치해줘”**라고 요청합니다. Codex가 [INSTALL.md](INSTALL.md)를 읽고 `Install.ps1 -CheckOnly`로 점검한 뒤 `Install.ps1`으로 경로 설정, HWPX·ODT 실행 환경 설치, 가능한 MCP 등록과 검사를 진행합니다.
3. 이미 설정한 업무·받은자료 경로와 Codex 설정은 재사용합니다. 처음에는 배포본의 `../업무`, `../받은자료`를 적용합니다. 원하는 위치가 있으면 함께 알려주면 됩니다. 실제 위치는 `.agent/index/delivery-system.json`에서 확인합니다.
4. 설치 결과에서 완료·실패·미검증 항목을 확인합니다. Codex 설치·로그인, 한컴오피스 설치·라이선스, 네트워크 또는 시스템 권한은 사람이 처리해야 할 수 있습니다. Codex CLI가 없으면 MCP 등록을 미검증으로 보고하며, 동명의 다른 연결을 덮어쓰지 않습니다.
5. 설치 후 [포함된 가상 실습자료](docs/실습자료/README.md)의 **ODT 기준본 2개와 공통 근거 1개**로 작년 안내문 갱신과 공문 본문 수정을 실행합니다. 원본·결과와 미확정 항목을 확인한 뒤, `$skill-creator`를 호출해 행사 준비표 스킬을 만들고 다른 메모로 재시험합니다. ODT 본문 실습과 한컴·전자결재 연결 검증은 구분합니다.

Codex에 이렇게 요청해도 됩니다.

> 설치해줘.

위치도 정하고 싶다면 “설치해줘. 업무는 E:\교사업무\업무, 받은자료는 E:\교사업무\받은자료를 써줘”라고 요청합니다. 수동 명령과 연결을 생략하는 옵션은 [INSTALL.md](INSTALL.md)에 있습니다.

## 폴더의 역할

```text
teacher-harness-release/   배포·실사용용 (기능 수정 폴더: teacher-harness-test/)
├─ AGENTS.md              매 작업에 적용할 짧은 공통 원칙
├─ README.md              시작 안내
├─ INSTALL.md             이 컴퓨터의 설정·설치·점검
├─ Install.ps1            점검·경로 설정·실행 환경 설치·MCP 등록
├─ Setup.ps1              개별 설정·선택 설치용 실행기
├─ docs/                  구조와 개인화 해설
├─ .agents/skills/        업무 설계 / 문서 처리 / 유지보수 / 전문 스킬 진입점
└─ .agent/
   ├─ index/              업무 경로와 실행 환경 설정
   └─ shared/             실행 코드·검증·빈 공문 양식·전문 처리 지침

업무/                     배포본의 업무 묶음 (테스트본 초기 위치: 테스트자료/업무/)
├─ 사용자가 제공한 업무흐름
└─ 분류번호_업무명/
   ├─ 주요 현재 문서
   └─ .ai/                선택 원본·내부 작업본·수정 이력·검증 기록

받은자료/                 배포본의 제공자료 원본 사본 (테스트본 초기 위치: 테스트자료/받은자료/)
```

업무와 받은자료 위치는 변경할 수 있습니다. 분류번호는 표시·정렬용이며, 과목이나 특정 학교의 업무 분류가 정해져 있지 않습니다. 새 분류는 사용자와 정하고 같은 연간 업무 묶음에서 재사용합니다.

## 기존 문서로 시작하기

HWPX·ODT·DOCX·XLSX·CSV·텍스트 문안 등 모든 산출물은 **사용자가 지정한 기존 초안/양식 → 등록된 현재본 → 명시적으로 선택한 이전 문서** 순으로 먼저 열어보고 내용을 채웁니다. 완료된 이전 문서도 쓸 수 있으며 기존 문단·표·배치는 보존합니다. 일정·대상·문서번호 등은 현재 근거로 확인합니다.

초안과 양식이 모두 없거나 파일을 읽을 수 없거나 후보 선택이 모호하면 해당 작성을 멈추고 필요한 파일 또는 선택을 요청합니다. ‘자료 없이 시작’, ‘새 초안’, ‘최종본’ 요청으로 새 양식을 만들지 않습니다. 포함된 범용 빈 공문 양식도 사용자가 선택하기 전에는 기본 기준본이 아닙니다. 질문·분석·업무계획 논의는 이 요구의 대상이 아닙니다.

## 제공자료 자동 보관

사용자가 파일을 제공하면 Codex가 [Receive-TeacherHarnessInputs.ps1](.agent/shared/Receive-TeacherHarnessInputs.ps1)을 호출해 설정된 `incomingRoot`의 받은자료에 원본 사본을 보관합니다. 원래 파일을 옮기거나 수정하지 않으며 SHA256을 확인합니다. 같은 내용은 재사용하고 같은 이름의 다른 내용은 별도 사본으로 보존합니다. 문서 접수의 `Start-HwpxWork.ps1 -UserProvidedFile`도 이 보관과 연결됩니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .agent/shared/Receive-TeacherHarnessInputs.ps1 -SourceFile 'D:\자료\기존계획.hwpx'
```

첨부의 실제 로컬 경로에 접근할 수 없으면 저장했다고 보고하지 않고 접근 가능한 경로를 요청합니다. 이 기능은 파일을 제공받을 때 실행하는 보관 절차이며 다운로드·첨부 감시기가 아닙니다.

## 요청에 맞는 지침

| 요청 | 적용할 스킬 |
|---|---|
| 업무 순서·분류·배치·반복 처리 개선 | [업무 설계](.agents/skills/work-planning/SKILL.md) |
| 학교 파일 작성·후속 수정·결과 게시·기준자료 선택 | [문서 처리](.agents/skills/hwpx-workspace-delivery/SKILL.md) |
| 공통 지침·실행 코드·설정 개선과 수리 | [유지보수](.agents/skills/workspace-maintenance/SKILL.md) |
| 공문·기안문 파일 작성 | [공문 초안](.agents/skills/official-odt-draft/SKILL.md) |
| 비정형 자료에서 근거를 찾아 항목 채움·대조 | [근거 확인](.agents/skills/evidence-fill-check/SKILL.md) |

필요한 스킬과 연결된 참고자료만 읽습니다. 전문 지침과 도구는 이 프로젝트 안에 두며, 개인 스킬 폴더에 중복 등록하지 않습니다.

## 업무 요청 예시

> 가상 학교의 독서행사 업무를 시작하자. 내가 제공한 기존 운영계획과 업무흐름을 먼저 열어보고, 현재 일정자료로 필요한 내용만 채워 줘. 기존 문단·표·배치를 보존하고 업무 분류가 없으면 필요한 결정만 물어봐 줘. 일정이 확인되지 않은 곳은 미확정으로 남겨 줘.

> 현재 운영계획의 행사 시간만 제공한 새 일정에 맞춰 수정해 줘. 나머지 문구와 서식은 보존해 줘.

> 이번 문서는 제출용으로 서식을 정리하고, 해당 문서의 페이지를 시각적으로 확인해 줘.

하네스의 기본 편집 범위는 내용 수정입니다. 서식 변경과 시각 검사가 필요한 요청은 해당 작업을 명시합니다. 이미 요청한 내용을 다시 승인받기 위한 절차는 아닙니다.

현재본 이름은 유지하고 작업·재시도와 이전본은 업무폴더 내부에 보존합니다. 결과 위치, 수행한 검사, 미확정 사항은 채팅으로 보고합니다. 업무현황 HTML과 별도 설명 파일은 요청했을 때만 만듭니다. 문서 작성 완료와 실제 결재·제출·통지 완료를 구분합니다.

## 포함 범위와 실행 조건

공통 실행 코드·검증 코드·빈 ODT 공문 양식은 포함합니다. 기존 학교 업무자료, 결과물, 가상환경 캐시, 개인 설정 사본, 빌드 산출물과 컴퓨터에 설치된 바이너리는 포함하지 않습니다.

배포 폴더가 있다는 것만으로 모든 기능이 실행되는 것은 아닙니다. HWPX 런타임, MCP 연결, 한컴오피스, Excel 등은 기능별로 별도 조건을 확인해야 합니다. 구조 검사 통과는 실제 한글 편집·페이지 렌더·외부 연결 성공을 뜻하지 않습니다.

원리와 개인 설정의 경계는 [구조와 개인화](docs/구조와개인화.md), 구체적인 설치·검사는 [INSTALL.md](INSTALL.md)를 참고합니다.

## 배포본 확인 결과

2026-10-06 합성 자료로 구조·PowerShell 구문·스킬 형식·문서 링크, 업무 접수·게시·수정 이력·반복 업무 연결·폴더 이동을 확인했습니다. 초기 상대 설정을 유지한 채 다른 작업 위치에서 실행하는 독립 검증도 통과했습니다. 파일 열기 도구의 빌드·유지보수 검증을 포함합니다.

이번 수정에서는 초안·양식 없이 중단하고 작성 폴더를 만들지 않는 조건, 업무계획 job의 문서 게시 금지, 기준본 사본과 해시 보존을 11개 검사로 확인했습니다. 제공자료 보관·동명 파일 충돌·반복 접수·실패 시 복구는 35개 검사, ODT의 명시 양식 요구·원래 서식 보존·출력 전 중단은 19개 검사로 확인했습니다.

실제 학교 자료는 실습용으로 복사하지 않았습니다. 네트워크 설치·현재 Codex의 MCP 연결·한컴/Excel 실제 처리·페이지 화면은 이번 배포 검증에 포함하지 않았습니다. 기능별 설치 뒤 해당 컴퓨터에서 확인합니다.
