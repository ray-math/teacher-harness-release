# 파일 접수와 게시

파일 접수·게시 절차는 파일 납품에 적용한다. 질문·분석·업무계획 논의·콘솔 보고만 할 때는 문서 job을 시작하지 않는다. 텍스트 문안도 [초안·양식 우선](reference-scope.md#초안양식을-먼저-열기)을 따른다. 사용자 제공 파일의 받은자료 보관은 job 생성 여부와 무관하게 수행한다. 명령은 작업공간 `.agent/shared/`에 있으며 선택한 명령의 인자가 필요할 때 해당 parameter block을 확인한다.

일반 에이전트 호출에는 `Start-HwpxWork.ps1`와 `Publish-HumanResult.ps1`의 `-Summary`를 사용한다. 상세 영수증은 같은 내부 경로에 그대로 저장되며, 응답에는 다음 행동에 필요한 경로·상태·개수·시간만 받는다. 상세 확인은 요약의 영수증 경로에서 필요한 필드만 읽는다. 기존 자동화가 전체 JSON을 사용하면 기본 출력을 유지한다.

## 접수

사용자가 제공한 접근 가능한 로컬 파일은 `Receive-TeacherHarnessInputs.ps1 -SourceFile <파일 경로들>`로 `.agent/index/delivery-system.json`의 `incomingRoot`에 자동 복사한다. 원본 바이트와 SHA256을 확인하고 같은 내용은 재사용하며 같은 이름의 다른 내용은 별도 사본으로 보존한다. 원본을 옮기거나 덮어쓰지 않는다. 첨부의 실제 로컬 경로에 접근할 수 없으면 보관 완료를 주장하지 않고 접근 가능한 경로를 요청한다. 이 실행기는 파일 제공 시 호출하는 보관 도구이며 다운로드·첨부 감시기가 아니다.

[업무폴더](work-folder.md)를 정하고 [기준자료 선택](reference-scope.md)의 우선순위로 기존 초안/양식을 실제로 연다. 현재 등록 파일을 후속 수정 기준으로 쓰고, 사용자 지정 기준본 교체가 있으면 사람 수정 보존과 함께 먼저 해결한다. 제공 자료가 충분하면 탐색을 끝낸다. 부족한 근거·양식만 `Find-HwpxContext.ps1 -WorkFolder <대상>`로 찾는다. 저장된 사용자 선택 또는 이번 요청에서 지정한 파일·폴더만 사용한다. 완료된 이전 문서도 구조의 기준으로 활용하되 올해 사실은 현재 근거로 확인한다. 기준본 부재·읽기 실패·모호한 선택은 관련 작성의 중단 조건이다.

`Start-HwpxWork.ps1 -RequestText <실제 사용자 요청>`으로 요청을 기록한다. 같은 요청의 재시도는 같은 `RequestId`(지정했을 때)와 요청 문구를 유지하고, 새 사용자 요청에만 새 요청 식별자를 사용한다. 완료를 위해 접수를 반복하여 게시 제한을 초기화하지 않는다. 새 요청의 기본 편집 범위는 내용 수정이며 서식·시각 검사 근거는 별도로 등록한다.

`Start-HwpxWork.ps1`에 선택한 모든 사용자 파일을 `-UserProvidedFile`로 전달하고 `-FormFile`, `-ReferenceFile`, `-HumanRevisionFile` 등 실제 역할을 지정한다. `-UserProvidedFile`은 받은자료 보관에도 연결되며 이미 보관한 같은 내용은 재사용한다. 반환된 job 경로를 사용하고 같은 목적·입력의 진행 중 job은 재사용한다. 도구는 선택 원본의 동일한 사본·역할·해시를 `.ai/originals`와 `.ai/sources.json`에 기록한다. 사용자가 선택한 원본·매뉴얼·이전자료를 직접 수정하거나 일괄 복제·변환하지 않는다.

일반 문서 접수의 `-Purpose Document`가 기본이다. 선택한 기준본은 `-FormFile` 또는 `-HumanRevisionFile`로 전달하며 등록된 현재본은 도구가 자동 확인한다. 사용 가능한 기준본이 없으면 `needs_input`을 보고 관련 작성을 멈추고 기존 초안/양식을 요청한다. `-UserProvidedFile`이나 `-ReferenceFile`만 전달했다고 그 파일이 양식으로 지정되지는 않는다. `-Purpose Workflow`는 실제 문서 작성 없이 업무 순서·배치를 저장할 때만 사용하며 문서 완료·게시 경로로 전환하거나 기준본 요구를 우회하지 않는다.

일부 등록 파일만 교체하면 `-SelectedFilesOnly -HumanRevisionFile <대상>`으로 접수하고 `Publish-HumanResult.ps1 -PartialUpdate`로 게시한다. 무관한 현재 파일은 읽거나 잠그지 않으며 기존 해시 시점도 그대로 둔다. 추가·이름 변경·제거는 전체 파일 집합 경로를 쓴다. 선택 대상·출처의 검사는 생략하지 않는다.

등록 파일 누락이나 미등록 루트 파일은 후속 접수·게시 전에 조정한다. 모호한 파일은 보존하고 필요한 처분만 확인한다. 등록 차이를 해소하려고 새 업무폴더를 만들거나 콘솔 보고로 파일 권위를 부여하지 않는다.

## 작성

반환된 `<업무폴더>/.ai/jobs/.../wip/docs/`에서 산출물당 현재 작업본 하나를 유지한다. 변환·원자 편집 실행에 필요한 후보 파일은 내부에 두고 중간본을 사람 업무폴더에 게시하지 않는다. 도구의 해시·영수증에 묶인 후보는 함부로 덮어쓰지 않는다. 필요한 변환본·실행 기록 외에 대화마다 사본을 늘리지 않는다. 서식·검증 범위는 [문서 스킬](../SKILL.md#내용과-서식-범위)을 따른다.

한글은 [한글 경로](hanword.md), 나머지는 해당 형식의 스킬을 사용한다. HWPX·ODT·DOCX·XLSX·CSV·텍스트 모두 기존 초안/양식을 먼저 확인하고 내용을 채우는 원칙을 따른다. 형식별 처리는 해당 형식의 실행기를 사용하며 CSV/XLSX/ODT에 HWPX 전용 상태 검사·변환을 추가하지 않는다. 취합은 기존 표 구조와 요청 밖 내용을 보존하고 실제 제출 항목의 누락·중복·단위·합계를 확인한다.

XLSX 작성·계산·저장은 현재 환경에서 지원되는 스프레드시트 스킬과 실행기를 사용한다. 시각 검사가 요청된 범위는 지원되는 렌더러로 확인한다. Windows에서 Excel이 있으면 `Export-XlsxPreview.ps1 -SourceFile <작업본> -OutputPdf <내부 새 PDF> -SheetName <시트> -RangeAddress <범위>`를 선택할 수 있다. 이 실행기는 별도 Excel 인스턴스만 사용·종료하고 원본 해시를 대조한다. 작성·저장·미리보기는 각각 종료 코드와 결과를 확인하며, 지원되는 렌더러가 없으면 화면 검증은 미완료로 보고한다. 기존 Excel을 종료하거나 설정을 바꾸지 않는다.

## 게시와 완료

요청한 파일 개수·배치·내용이 모두 완성되고 해당 변경의 검사가 끝나면 `Complete-HumanDraft.ps1 -JobPath <job> -SourceFile <완성 작업본들> -TargetRelativePath <요청한 결과 경로들> -Stage Review|Final -ChecksCompleted content,integrity`로 내부 완료 영수증을 만든다. 이 단계는 사용자에게 추가 승인을 요청하는 절차가 아니다. `content`는 요청한 내용·누락·요청 밖 내용 보존 대조, `integrity`는 해당 형식의 필수 무결성 검사를 실제 마쳤을 때만 기록한다. 검증 영수증이 있으면 `-CheckReceiptFile`로 연결한다. 완료 영수증은 요청·활성 범위·파일 해시·결과 경로에 묶이며 변경 시 다시 확인한다.

`Publish-HumanResult.ps1`로 요청된 Review/Final 단계에 완성된 결과 집합을 한 번 게시한다. 같은 요청의 중간 수정·자동 재시도를 추가 게시로 처리하지 않는다. 동일 결과 재시도는 현재본과 이력을 그대로 재사용한다. 새 사용자 수정 요청은 그 요청을 후속 접수한 뒤 같은 현재 경로에 반영한다. 해당 작업의 권위·양식·기준본·정규화·open-safety 영수증을 전달한다. 일치하는 성공 영수증은 재사용하고 다른 연산의 영수증으로 대체하거나 게이트를 낮추지 않는다. 사용자 출처 선택 기록이 없는 legacy job은 접수를 보완한다.

`-SourceFile` 순서에 맞춰 `-TargetRelativePath`를 지정한다. 폴더 단계라면 `01_운영계획 검토·기안/운영계획.hwpx`, 단일 파일이면 `02_대상 명단 확인.xlsx`처럼 전달한다. 후속 작업은 이동 요청이 없는 한 현재 경로를 유지한다. 게시를 끝내려고 현재 파일을 수동 복사하지 않는다.

도구가 출처 해시, 현재 파일 집합, 실제 교체 파일의 내부 보존 이력을 확인·기록하고 `wip/receipts/work-publish.json`을 남긴다. 동일 내용 재게시에는 새 이전본을 만들지 않는다. TXT는 명시적 TXT 요청과 `-ExplicitTextArtifact`가 필요하다. HTML 갱신은 별도 요청의 `-UpdateConsole`만 사용한다.

결과 경로·실제로 수행한 검사·미확정 사항을 채팅으로 보고하고 요청된 단계에서 끝낸다. 파일 재열기·HTML 미리보기는 실제 한컴 렌더링 검증이 아니다. 중간물 정리가 필요할 때만 [보관 규칙](storage.md)을 읽는다.
