# 업무폴더 선택과 배치

학교 파일을 접수·생성·수정하기 전에 출력 배치를 확인한다. 강의 기본값 `outputLayout: "flat"`에서는 `humanCabinet`인 바탕화면 Output 자체를 대상으로 사용하고 업무별 하위폴더를 만들지 않는다. 내부 job과 이력은 숨김 `.ai/`에 둔다. 아래 폴더 선택 절차는 기존 폴더형 배치와 명시적으로 선택한 기존 업무에 적용한다. 새 대화·문서·내부 job은 새 업무가 아니다. 일반 질문과 시스템 유지보수는 사람 업무폴더를 만들지 않는다.

## 기존 업무 찾기

같은 대화에서 이미 선택·확인한 업무폴더는 현재 경로와 등록이 유효하면 재사용한다. 후속 문구 수정마다 보관함을 다시 열거하지 않는다. 아래 후보 조회는 새 세션, 대상 미확정 또는 이름·업무 범위 변경으로 재선택이 필요할 때 수행한다.

1. 사용자가 지정한 폴더를 우선하고 현재 경로를 확인한다. 이전자료·양식 폴더는 납품 목적지가 아니다.
2. `.agent/index/delivery-system.json`의 `humanCabinet`과 보관함 바로 아래 폴더 이름을 확인한다. 등록 조회는 `WorkRegistry.ps1`로 각 업무의 `.ai/work.json`을 읽는다. 등록되지 않은 기존 폴더도 포함한다. 재귀 자료 검색이나 reparse 경로 탐색은 하지 않는다.
3. 목적·학년도·학기·행사·회차가 맞는 후보의 `.ai/work.json`만 필요한 만큼 읽는다. 계획·명단·붙임·결과 보고가 같은 업무이면 같은 폴더를 쓴다. 제목 불일치만으로 새 업무를 만들거나 과거 양식에서 올해 회차를 계산하지 않는다.
4. 적합한 폴더가 명확하면 선택 경로를 알리고 진행한다. 후보가 여러 개이면 필요한 선택만 묻는다. 적합한 폴더가 없거나 분리를 명시적으로 요청했을 때만 신규로 만든다.

기존 업무는 `Start-HwpxWork.ps1 -Mode FollowUp -WorkFolderName <실제 이름>`에 기존 `-TaskTitle`을 유지한다. 새 행동은 `-Goal`과 `-IntakeSummary`, 선택 이유는 `-DecisionReason`에 적는다. 신규 `-Mode New`의 이유에는 기존 후보 확인 결과 또는 사용자 분리 요청을 남긴다. 별도 폴더선정 보고서는 만들지 않는다.

등록 차이·누락은 [접수와 게시](artifacts.md)의 전체/선택 파일 경로로 해결하며 `New`로 우회하지 않는다. 이름 변경 후에는 등록과 실제 경로를 먼저 확인하고 옛 job 경로로 사라진 폴더를 재생성하지 않는다. 폴더 선택은 기존 자료의 병합·이동·삭제나 Codex 대화 제목 변경을 허가하지 않는다.

선택한 업무의 `Get-WorkContext.ps1 -WorkFolder <경로>`로 공통 처리 방법과 개별 예외를 읽는다. 같은 요청에서 읽은 결과는 재사용한다. 새 회차는 사용자가 정한 반복 업무와 맞으면 [반복 업무 기록](../../work-planning/references/repeated-work.md)에 따라 같은 그룹으로 연결한다. 연결되지 않은 새 업무나 다음 학년도로 설정을 추정해 상속하지 않는다.

## 사람에게 보이는 배치

강의의 평면 배치에서는 Output 바로 아래에 `00_제목.확장자`, `01_제목.확장자`로 결과를 게시한다. 기존 파일명·경로를 유지하고 새 결과만 다음 빈 번호를 사용하며 업무별 하위폴더를 만들지 않는다. 기존 업무를 이 배치로 자동 이동하지 않는다.

기존 폴더형 배치의 신규 업무는 설정된 보관함 아래에 요청의 업무명으로 만든다. 분류번호 때문에 질문하거나 중단하지 않는다. 이름을 생략하면 실행기가 TaskTitle에서 안전한 이름을 정한다. 같은 업무는 기존 폴더와 등록을 먼저 재사용하고 이미 정한 번호 폴더·분류는 보존한다. 분류 체계 설계는 별도 요청 때 [반복 업무 기록](../../work-planning/references/repeated-work.md)에 저장한다. 기존 날짜 접두 폴더도 임의로 바꾸지 않는다. 아래 단계별 폴더 배치는 폴더형 설정에서만 적용한다.

- 여러 자료·산출물이 필요한 단계: `01_운영계획 검토·기안/`처럼 순서와 행동을 이름에 쓴다.
- 한 파일로 끝나는 단계: 루트의 `02_대상 명단 확인.xlsx`처럼 번호 파일을 우선한다. 빈 가짜 문서나 미사용 분류 폴더를 만들지 않는다.
- 주요·상시 참고 자료: 업무 루트에 현재본 한 벌만 둔다. 필요하면 `00_`를 사용하며 여러 단계에는 같은 파일을 연결한다.
- 중간 업무 추가: 기존 ID·경로를 유지하고 `01-01_` 등 삽입 번호를 사용한다. 순번 재정렬·이동을 요청받으면 이동 매핑과 현재 등록·참조를 함께 갱신한다. 콘솔은 별도 요청 때 갱신한다.

단계 적용은 [업무흐름 스킬](../../work-planning/SKILL.md), 게시 목적지는 `Publish-HumanResult.ps1 -TargetRelativePath`로 지정한다. 단일 파일의 번호만 정하려고 복잡한 계획을 만들 필요는 없다. 현재본 이름은 안정적으로 유지하고 실제 교체본은 [보관 규칙](storage.md)에 따른다.

기존 `previous_versions`·이전자료·복구 기록은 보존한다. 새 이전연도 폴더나 이전자료 색인을 만들지 않고, 필요한 이전자료만 사용자 지정 위치에서 접수한다.
