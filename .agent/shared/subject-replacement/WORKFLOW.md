# Native subject replacement

Use only for a user-requested replacement of entire named subject plans inside a current grade compilation. This route does not authorize changing other subjects or grading decisions. Follow normal selected-source intake and current-human hash checks.

Prepare a worker for the selected documents under the active job's `wip/scripts/`; there is no reusable worker stored in an old job. Use an isolated Hancom COM instance and the installed official file-access module. Establish unique top-level paragraph boundaries from the exact current revision, move to the main text story, select the named subject, and confirm the selected full text before deletion. Insert the received document using native InsertFile with KeepSection/KeepCharshape/KeepParashape/KeepStyle enabled. Work on job copies only. Save to separate HWPX files, reopen in Hancom, and require exact full text equal to the old document with only those selected blocks replaced. Native text decoding ignores whitespace and decodes entities; it is not visual inspection.

Publication requires a `hwpx.subject-replacement-publication/v1` manifest under the active job's `wip/receipts`. Use `Publish-HumanResult.ps1 -SubjectReplacementReceiptPath <manifest>` with the complete changed grade set. The route cannot be combined with the existing form, non-form, or whole-document merge routes. `Assert-SubjectReplacementPublication.ps1` runs `verify.py` and rejects missing/changed intake sources, incomplete outputs, altered native receipts/worker hashes, changed subject order, or any unapproved table-cell/topology/size/margin difference. Replacement tables must match the normalized received forms. Explicit user cell corrections require their before/after values, locations, authorization and matching native patch receipt. All other tables must match the current human bases.

Package validation uses the existing `hancom-native/verify_package.py` checker. It retains the unmodified upstream report; only the previously verified python-hwpx 6.3.0 inline-control text-position correction can apply. No XML/package bytes are rewritten and no other validator is disabled. Native full-text and table checks are separate requirements, not replacements for package checks.

Run `test_verify.py` for lineage guard cases. `realHancomVerified=false` remains appropriate because no page-by-page visual review was requested. Do not describe native reopening as visual review.
