# 공개 스킬 참고와 추가 제안

아래 공개 스킬은 참고 자료이며 이 배포본의 필수 설치 목록이 아니다. 공식 편람·기관 양식·현재 사용자 지정을 우선하고, HWPX 전용 구현을 ODT에 그대로 이식하지 않는다. main 브랜치는 변경될 수 있으므로 실제 도입 시 해당 버전을 다시 확인한다.

| 참고 | 확인한 유용한 부분 | 현재 판단 |
|---|---|---|
| [jkf87/hwpx-skill](https://github.com/jkf87/hwpx-skill/blob/main/SKILL.md) | 사실·본문·표 셀·붙임의 보존 검사, 파일/렌더 검사 구분, 마지막 쪽 단독 문단 점검 | 보존과 검증 구분은 이미 있다. 제목/표 분리 및 마지막 쪽 단독 문단 점검을 추가 후보로 제안한다. |
| [chrisryugj/kordoc의 gongmunseo](https://github.com/chrisryugj/kordoc/blob/main/.claude/skills/gongmunseo/SKILL.md) | 기안문·보고서·계획서·통지·회의록 구분, 중첩 단계별 항목기호 생성, 날짜/기간/붙임 표기 | 종류와 단계 구분을 참고한다. 글꼴·여백 프리셋은 기관 양식과 현재 사용자 지정을 대체하지 않는다. |
| [airmang/hwpx-plugins](https://github.com/airmang/hwpx-plugins) 및 설치된 HWPX 스킬의 정합성 검사 | 붙임 참조와 실제 목록 대응, 표/그림 번호 연속성 검사 | ODT에서는 같은 검증 목적을 별도 구현해야 한다. HWPX용 도구 실행을 ODT 검증으로 보고하지 않는다. |

공개 스킬마다 글꼴·줄간격·빈 줄 정책이 다르며 공식 기준과 개별 편집값이 혼재한 참조도 있다. 설치된 HWPX 규칙 문서의 '붙임 뒤 끝을 단독 문단으로' 같은 설명도 편람의 마지막 붙임 뒤 2타 규칙보다 우선하지 않는다. 외부 스킬의 기본값·명령·새 승인 절차는 자동 채택하지 않는다.

## 배포 예제의 편집 선택

표의 실제 귀속 항목 단계에 따라 왼쪽 테두리를 정렬한다. `가.`는 `.`, 하위 `1)`는 `)`, `(가)`도 마지막 `)`의 문자 시작점이다. 원문자는 기호 시작점에 맞춘다. 실제 기호 위치와 글꼴 폭으로 계산하고 들여쓴 만큼 사용 가능 폭을 줄인다. [표 공통 편집 기준](writing-guide.md#표-공통-편집-기준)에 적용 범위를 기록했다.

## 아직 채택하지 않은 추가 제안

1. **제목·표 분리 방지:** 제목만 앞쪽 끝에 남고 표는 다음 쪽으로 넘어가는 현상, 마지막 쪽에 붙임 한 줄만 남는 현상을 렌더 검토 때 점검한다. 내용 삭제나 글자 축소로 강제 해결하지 않는다.
2. **참조 대상 대조:** 본문의 '붙임 2 참조'와 실제 목록 2번, 표 번호, 붙임 제목/수량을 교차 확인한다. 목록 작성과 실제 전자결재 첨부 완료는 구분한다.
3. **중복 정보 대조:** 같은 날짜·기간·금액이 본문·표·붙임에서 다르면 표시한다. 미확정 값은 근거 없이 자동 수정하지 않는다.
4. **한 행의 의미 보존:** 한 대상자의 행이 쪽 사이에서 부자연스럽게 끊기는지 점검한다. 한 행 자체가 한 쪽보다 큰 경우는 별도 처리한다. 제목행 반복은 이미 공통 기본값에 있다.

위 후보는 사용자가 채택하기 전 새 자동 수정 규칙으로 적용하지 않는다. 현재 검사를 설명할 때도 아직 구현하지 않은 항목을 통과했다고 하지 않는다.
