# 업무포털 붙여넣기 ODT 참고 기록

## 적용과 확인 범위

이 문서는 과거 붙여넣기 실험과 유지보수용 `paste_odt.py` 도우미의 참고 기록이다. **업무 기본 생성 경로가 아니다. 모든 업무 문서는 사용자가 지정한 기존 초안/양식을 실제 읽고 기존 구조에 내용을 채운다. 초안/양식이 없으면 반드시 멈춰 질문한다.** 빈 ODT 생성이나 아래 예제는 양식이 없을 때의 대체 경로로 사용하지 않는다. 기존 원본 형식을 유지하고 ODT로 자동 변환하지 않는다. 실제 업무 CLI는 [기존 ODT 양식 채우기](odt-workflow.md)의 `--template` 필수 경로만 지원한다. **실제 기안기의 서식 유지와 첫 문단 동작은 대상 환경에서 확인해야 하며**, 패키지 검사를 모든 기안기 버전의 호환 완료로 확대하지 않는다.

첫 붙여넣기 조각은 대상의 기존 문단과 합쳐져 대상 서식의 영향을 받을 수 있다. 이 설명은 기안기 내부 코드나 클립보드 자료를 추적한 결론이 아니다. 글꼴 선언·상위 스타일·번호 처리 중 하나를 확인 없이 원인으로 단정하지 않는다. 같은 `바탕글` 이름도 같은 스타일 정의를 보장하지 않는다.

## 생성과 전달

### 누름틀 원인과 읽어오기 분기

[한컴 담당자 답변(2025. 4. 2.)](https://forum.developer.hancom.com/t/settextfile-api/2375/2)은 누름틀이 있는 첫 문단을 내용이 있는 문단으로 처리하여 기존 속성을 따르고, 줄바꿈 뒤에는 입력 문단 속성을 따른다고 설명한다. 이 API 설명만으로 대상 기안기 버전의 클립보드 경로를 확인했다고 판단하지 않는다.

읽어오기를 요청하면 본문 전용 ODT에 겉모양만 추가하지 않는다. 사용자가 제공한 결재 ODT 양식의 `NormalField…¡본문¡…` 시작·끝과 `CellField…¡필드명¡…` 셀 필드를 보존해야 한다. 값 지우기와 필드 삭제는 다르다. 문서번호·서명·연락처·공개구분의 과거 값을 비우더라도 필드 컨트롤은 남긴다. 순번은 저장 시 달라질 수 있으므로 의미상 필드명·속성·위치·중복·본문 경계로 대조한다. 일반 ODT 생성, ZIP 무결성, Word 렌더링을 결재문서 읽어오기 성공으로 간주하지 않는다.

`scripts/approval_fields.py`는 구조가 일치하는 현재본과 제공 원본의 머리·꼬리 양식에서 누락된 필드만 복원한다. 본문 첫/마지막 문단은 명시적으로 지정하고, 옛 결재값을 복원하지 않는다. 일반 양식 자산이 실제 기안기용 결재 필드를 갖췄다는 보장은 없으므로 `general/internal` 출력도 필드 검사 및 실제 읽어오기 확인 전에는 호환 완료로 표시하지 않는다. 해당 기안기의 읽어오기 성공과 첫 문단의 선택한 서식 유지까지 확인해야 이 경로의 해결을 보고할 수 있다.

### 본문 전용 붙여넣기

첫 문단의 붙여넣기 호환성은 이 배포본에서 보장하지 않는다. 본문 글꼴 명시·기본 스타일·본문 경계 필드만으로 해결됐다고 판단하지 않는다. 빈 문단 유지는 현재 사용자가 받아들일 때만 임시 우회로 안내하며, 빈 줄 없는 결과가 요구되면 이 우회로 요구를 충족했다고 표시하지 않는다.

기안기 조정 문의 시 사용자 메뉴와 개발자 API를 구분한다. [한컴 답변(2025. 2. 26.)](https://forum.developer.hancom.com/t/settextfile-html/2259)은 웹한글의 `InsertFile`에서 `KeepStyle`, `KeepCharshape`, `KeepParashape`, `KeepSection` 설정을 안내한다. 현재 K-에듀파인 ODT 컨트롤에 적용되는지, 사용자 메뉴로 제공되는지는 미확인이다. 이를 사용자가 켤 수 있는 설정으로 안내하거나 운영 중인 포털에 코드를 주입하지 않는다.

- 아래 내용은 `paste_odt.py`의 합성 문서 검사 설명이다. 새 `OpenDocumentText()`에서 시작하므로 기존 초안/양식을 채우는 업무에는 사용하지 않는다. `draft_odt.py --form paste` 경로는 제거됐으며 `--template`을 생략할 수 없다.
- `Standard` 기본 문단 스타일을 정의하고 한글·서양 문자·복합 문자에 모두 굴림체 12pt를 명시한다. 글꼴 선언은 `GulimChe → 굴림체` 한 종류만 둔다. 본문/표의 문단과 span에 같은 글꼴 정보를 명시한다. 줄간격은 예제 기본값 123%이며 `typography.line_height`(예: `160%`)를 지원한다. 장평 100%, 자간 0을 적용한다. 기관 양식과 현재 사용자 지정이 우선한다.
- 파일 처음에 같은 서식의 **빈 문단 정확히 하나**를 둔다. 공백 문자, 숨은 문자, Shift+Enter 줄 나눔, 문단 위 여백으로 대체하지 않는다. 공문 작성 규정이 아니라 붙여넣기 호환성 처리이며 붙임 앞 빈 문단과 목적이 다르다.
- 합성 실험 문서에는 제목·기관명·결재란·로고를 복사할 본문에 섞지 않는다. 관련 항목부터 표·붙임·끝 표시까지 포함한다. 업무용 전체 공문은 사용자가 선택한 실제 기존 양식만 쓰며 `--form general/internal`이 자산을 자동 선택하지 않는다.
- 파일을 다시 열어 **Ctrl+A → Ctrl+C**로 첫 빈 문단과 마지막 문단까지 포함하도록 안내한다. `1. 관련`부터 드래그하면 우회가 사라진다. 이 예제의 호환성 처리 방식은 기안기에 붙인 뒤에도 첫 빈 문단을 유지하는 것이다. 빈 줄을 삭제해도 된다고 재안내하지 않는다. 빈 줄 없는 결과가 필요하면 대상 첫 문단 서식/붙여넣기 처리의 추가 확인이 필요하며, 빈 줄을 숨기거나 무수정 성공을 주장하지 않는다.
- 단순 직사각형 표와 문단 전체 강조를 지원한다. 병합 셀·그림·문단 내 혼합 강조 등 미지원 내용을 평탄화하거나 버리지 않는다. 필요한 별도 경로를 선택한다.

## 유지보수용 도우미 입력 (업무 생성 호출 아님)

표가 없는 문안은 기존 `title/related/body/attachments` JSON을 사용한다. 표가 있으면 `blocks`에 완성된 본문 순서를 전달한다. `blocks`와 `body/related/attachments`는 함께 사용하지 않는다. 일반 문단은 문자열, 문단 전체 강조는 `{"text":"내용","bold":true}`이다.

```json
{
  "title": "검토 요청",
  "blocks": [
    "1. 관련: 00고-0000(0000. 0. 0.)",
    "2. 다음과 같이 검토를 요청합니다.",
    {"table": {
      "headers": ["구분", "내용"], "rows": [["자료", "ABC 123"]],
      "column_widths_mm": [35, 137], "column_roles": ["short", "text"],
      "anchor_item": {"marker": "2.", "item_start_mm": 0}
    }},
    "  가. 확인 사항: 자료 검토",
    "",
    "붙임  검토 자료 1부.  끝."
  ]
}
```

`blocks`의 항목 번호·붙임·끝 표시는 작성자가 완성하고 검토한다. 표 귀속 항목은 실제 문맥으로 지정한다. 해당 단계 마지막 기호에 표를 맞추고 본문 폭 안에 놓는다. 기존 계층 내어쓰기, 붙임 번호 뒤 공백 한 칸, 붙임 앞 빈 문단, 표 앞뒤 6pt·셀 여백 원칙을 유지한다.

## 검사와 안내

내용 왕복 일치, MIME/ZIP/XML/manifest·재열기, 첫 빈 문단, 단일 글꼴 선언, 세 문자 영역 글꼴·크기, 줄간격, 문단/문자 스타일 참조와 상위 스타일의 존재·순환을 검사한다. 표 내용·구조, 붙임 수·순서, 굵기·항목 위치는 입력 계약과 별도 대조한다. 입력 자체의 누락이나 잘못된 표 귀속은 파일 무결성으로 증명되지 않는다.

글꼴 검사는 본문에 실제 사용된 스타일만 보지 않는다. 글꼴 선언의 참조명과 실제 가족명, 미사용 스타일, paragraph/text 기본 스타일, 한글·서양·복합 문자 속성을 포함한다. `신명조` 문자열 전체 검색 결과만으로 판정하지 않는다. 진단 문구에 이 단어가 있어도 서식 잔재가 아니며, 선언 이름이 임의의 ID여도 실제 가족명이 다르면 실패다. 새 붙여넣기 문서의 크기 12pt, 장평 100%, 자간 0, 선택한 줄간격(기본 123%)을 저장 후 검사한다.

실제 기안기 붙여넣기 확인은 사용자 시험 또는 해당 기안기의 직접 확인 근거로만 말한다. Word/PDF와 ODT 속성 검사는 그 대체 증거가 아니다. 새 파일마다 기안기 시험을 했다고 표시하지 않는다. 정상 내용까지 매번 사용자에게 다시 서식 지정하도록 안내하지 않는다. 첫 문단을 포함한 실제 호환성은 대상 기안기에서 확인한다.
