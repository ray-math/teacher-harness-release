# 공문 고급 편집과 예외 처리

일상적인 초안은 [기본 절차](../SKILL.md)로 끝낸다. 아래는 요청 충돌·자리표시자 양식·새 본문 표·서식 변경·결재 포털 읽어오기·호환성 문제에 해당하는 절만 읽는다.

## 요청 충돌과 문서 종류

제공 원문의 본문·붙임·결재 범위를 함께 읽어 요청한 처리가 이미 포함돼 있는지 확인한다. 붙임 파일이 있다는 사실만으로 결재 완료나 별도 공문 불필요를 확정하지 않는다. 같은 업무의 시행계획과 발송 공문은 다른 문서 종류다. 예를 들어 시행계획에 안내문이 포함돼 있으면 기존 계획·붙임 수정인지 별도 발송 공문인지 현재 요청과 근거로 구별한다.

실제 충돌로 선택이 필요하면 근거·문제점·대안을 제시하고 질문한다. 답변 전에는 선택에 달린 처리를 보류하되 독립적인 원문 확인은 계속한다. 침묵을 답변으로 간주하지 않으며 이미 확정한 선택은 다시 묻지 않는다.

## 요청 범위와 과거 사실

학년도·학기·회차·날짜·대상·관련·붙임 등 달라지는 범위만 현재 근거로 바꾼다. 문체 개선을 이유로 전체를 재작성하거나 안내 항목을 늘리지 않는다. 과거 문서의 날짜·회차가 어긋나도 자동으로 수정하거나 다음 회차를 계산하지 않는다. 새 초안의 사실은 새 업무 근거로 정한다.

업무 카드의 작성자·담당자 정보와 메시지 말투는 본문 입력 근거가 아니다. 명시적인 개별 지시 없이 자기소개·대화용 성명·인사를 추가하거나 학교 명의 인사를 담당자 소개로 바꾸지 않는다. 결재란·담당자란이나 업무 대상자의 성명은 확인된 근거와 요청 범위에 따라 처리하며 최신 사용자 정정이 우선한다.

내용 검토에서는 실제 변경 문장이 요청·근거에 대응하는지 확인한다. 패키지·서식·텍스트 추출 성공이 이를 대신하지 않는다. 작성에 무관한 인명·등록부를 채팅·광범위 색인으로 옮기지 않는다. 외부 검색에는 일반 작성요령만 보내며 학교 내부 내용·개인정보를 검색어에 넣지 않는다.

## 지원 자리표시자가 있는 기존 ODT

[ODT 실행·입력 절차](odt-workflow.md)를 따른다. `draft_odt.py`는 명시 선택한 기존 ODT의 지원 자리표시자만 채우며 일반 현재본을 재생성하지 않는다. `--template`은 필수다. `--form`이나 내부결재라는 이유로 `assets/general.odt`, `assets/internal.odt`를 자동 선택하지 않는다. 기준본 미지정·미지원 구조는 `needs_input`으로 중단하고 출력하지 않는다. HWPX에는 ODT 패키지 편집을 적용하지 않는다.

자리표시자 도구는 `.agent/index/odt-runtime.json`의 `pythonPath`로 `scripts/run_odt.py`를 실행하며 `dependencyDirectory`를 `--deps`로 전달한다. 기록이나 실제 실행기·의존성이 없으면 [설치 안내](../../../../INSTALL.md)를 따른다. 일반 문서 작업 중 자동 설치·갱신하지 않는다. 설치 기록은 컴퓨터별 정보이며 ZIP 배포 자산이 아니다. 일반 ODT의 `edit_existing_odt.py`는 별개로 표준 라이브러리만 사용한다.

## 서식 변경·새 본문 표

원래 서식은 기본 절차대로 보존한다. 배포 자산의 굴림체 12pt·123%는 자산 예시이며 다른 문서의 기본값이 아니다. `typography`는 명시적인 서식 변경 요청에만 넣고, 입력한 속성만 자리표시자 교체 문단과 본문에 적용한다. 문서 전체 글꼴 정리나 내어쓰기 재계산은 기본 작업이 아니다.

사용자가 새 본문 표를 요청한 경우 [표 공통 편집 기준](writing-guide.md#표-공통-편집-기준)을 적용한다. 항목 마지막 기호(`.` 또는 `)`)에 왼쪽 테두리를 맞추고 표 앞뒤 6pt, 들여쓰기를 제외한 본문 폭 이내 배치, 내용에 맞는 열 너비·정렬, 셀 여백·글꼴 통일을 기본으로 한다. 기관 지정 양식·별도 요청이 우선하며 기존 표를 일괄 수정하는 근거로 쓰지 않는다.

[기본 서식 검사](writing-guide.md#기본-서식-필수-검사)는 명시적인 엄격검증·서식 수정 범위에만 적용한다. 번호 단계·연속성의 의미 확인과 실제 화면 확인은 파일 속성 검사와 별개다.

## 결재문서 읽어오기·호환성

결재문서 읽어오기 요청은 [누름틀·필드 보존 경로](portal-paste.md#누름틀-원인과-읽어오기-분기)를 따른다. 제공 결재 ODT의 본문 시작/끝 및 셀 필드 구조를 보존하고 과거 값만 비운다. 붙여넣기 전용 파일이나 겉모양만 같은 일반 ODT를 읽어오기 가능한 결재문서로 안내하지 않는다.

서식 보존과 호환성은 별도다. 기존 문서를 단일 글꼴 프로필로 정리하지 않는다. 파일 검사 통과를 기안기의 첫 문단 문제 해결로 보고하지 않는다. 사용자 PC에서 같은 실패를 반복하지 말고 새 원인 근거·구체적 검증 항목이 있을 때 허용된 범위에서 확인한다.

## 보조 도구의 범위

아래 경로는 스킬 폴더 기준이다. 상세는 [ODT 절차](odt-workflow.md)와 [공식 작성 기준](writing-guide.md)을 참고한다.

- `scripts/edit_existing_odt.py`: 주소와 정확한 before/after로 leaf 문단/span 또는 직접 텍스트 segment를 교체한다. inspect → 계획 → dry-run → apply 순서를 지킨다.
- `scripts/paste_odt.py`: 유지보수용 합성 문서·과거 호환성 실험용이다. 새 빈 문서 도우미이므로 기존 양식 대체 경로가 아니다.
- `scripts/basic_format.py`: 실제 글꼴 폭 기반 번호·붙임 내어쓰기와 속성 검사. 의미 검토·실제 화면 확인은 별도다.
- `scripts/font_profile.py`: 배포 자산·합성 문서 검사 전용이며 현재 사람 문서의 정규화 도구가 아니다.
- `scripts/body_table.py`: 지정 열 너비·역할로 새 본문 표를 만드는 도우미다. 결재란·기존 양식 표를 일괄 수정하지 않는다.
- [자산 출처](template-provenance.json): 빈자산 해시·개인정보 검사 기록이며 과거 공문의 사실 근거가 아니다.
- [스킬 비교](skill-comparison.md): 공개 스킬 비교와 제안이며 미채택 제안을 기본 규칙으로 적용하지 않는다.
