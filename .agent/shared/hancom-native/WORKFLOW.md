# Whole-document merge

Use for appending entire HWP/HWPX documents in a specified order. Use existing intake/delivery rules for human results; these commands produce a checked job artifact, not a published result. Do not convert HWP first or inspect every table to concatenate documents. Do not install additional plugins.

1. Resolve the human work folder, base and ordered append inputs. Use the school job path returned by intake, within that work's `.ai/jobs/`; do not construct an `.agent/jobs` destination. Register all selected inputs with `-UserProvidedFile`, and the base as the current human revision. Write a JSON array of selected absolute paths, base first, in that job. The model supplies paths/order, not content or hash calculations.
2. Run `powershell -NoProfile -ExecutionPolicy Bypass -File .agent/shared/New-HancomMergePlan.ps1 -JobPath <job> -InputList <json> -OutputName <name.hwpx>`. It preserves selected copies and writes `native-plan.json`. Copies here do not replace cabinet intake provenance.
3. Run `powershell -NoProfile -ExecutionPolicy Bypass -File .agent/shared/Invoke-HancomMerge.ps1 -Manifest <job>/native-plan.json`. Read the compact result. `ok=true, stage=verified` means native reopening, full extracted source text in order (whitespace ignored), unchanged input hashes and package checks passed. It does not claim visual inspection or publication.

   In Codex on this Windows desktop, run the native merge command with `exec_command.sandbox_permissions="require_escalated"` (reason: use the installed Hancom app and the already authorized official security module on selected copies). The sandbox can expose a different user registry view and report `security_module_unavailable` although setup is complete. That error from a sandbox call calls for the authorized desktop execution context, not reinstalling plugins. The runner keys receipts by visible module configuration so a sandbox failure does not poison the desktop attempt.
4. For actual delivery, copy the verified output byte-for-byte to `wip/docs/<current human filename>` and stage the other current files unchanged in the same folder. Call `Publish-HumanResult.ps1` with the complete current file set and `-NativeMergeReceiptPath <successful native receipt>`. This branch checks the ordered plan, current human base/intake hashes, complete insertion/text checks, native reopen and unmodified upstream open-safety; it is not `FormGateNotApplicable`. Retain the user's existing filename, even when it contains `(안)`. The publisher preserves the replaced set. Add `-UpdateConsole` only when console creation or refresh was explicitly requested. Formatting cleanup remains opt-in.

The worker uses native InsertFile with character/paragraph/style/page preservation. The official file-access module is already installed for this user. On `security_module_unavailable`, inspect setup health once; do not fall back to repeated approval clicks. On timeout, the job lock remains and the last receipt identifies the stage: inspect the worker's state before retrying. Do not kill unrelated Hancom processes. Matching successful requests reuse the receipt and verify the output hash. Matching failed requests return their failure without repeating. Changed input, output or implementation needs a new reviewed attempt; never remove an output just to make a retry run.

Default timeout is 120 seconds. Rendering is off for ordinary content-only merges. Optional `renderPdf` requires active job `visual_review` scope backed by the explicit user request; launcher, worker, receipt reuse and publication recheck it. A PDF diagnostic does not itself prove visual verification. Native reopening, content order and package safety remain mandatory without optional rendering. The installed python-hwpx 6.3.0 adapter records the upstream and corrected reports if it must count inline line-break controls; it never rewrites XML or disables other validation. The direct HWP/HWPX benchmark passed the unmodified upstream check.

Measured 2026-09-08: base + 7 subject plans, original HWP/HWPX copies, about 2.9 seconds inside the worker; no document approval clicks. Second identical call reused the result. A fresh Luna subagent also selected the real inputs and completed the merge after the desktop-execution guidance and environment-aware failure cache were corrected. Parent assistance was needed for those initial fixes and publication; do not describe the first evaluation as fully independent. Windows must be awake with the user session available. Other unexpected dialogs cause a bounded failure rather than a false success.
