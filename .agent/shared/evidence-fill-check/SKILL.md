# 자료 근거 기반 채움·대조

대화와 제공 자료에서 대상 파일·항목, 근거 자료, 연결 기준과 확인/수정 범위를 정한다. 현재 사용자 파일을 기준으로 삼고, 이미 정한 기준을 다시 묻지 않는다. 충분한 입력이 있으면 이전 연도까지 검색하지 않는다.

## 요청에 맞는 경로

| 요청 | 적용 경로 |
|---|---|
| 값 확인만 | 해당 파일 형식의 읽기 → 항목 대조 → 채팅 보고. 문서·접수 기록·현재 파일 등록을 변경하지 않는다. |
| 근거에 따라 실제 수정 | 아래 수정 조건과 해당 파일 형식의 편집 도구. 학교 파일의 접수·게시에는 [납품 스킬](../hwpx-workspace-delivery/SKILL.md)을 사용한다. |
| 같은 한글 표의 과목별 학생 명단을 실제 취합 | [명단 취합 실행기](../collect-hwpx-rosters/SKILL.md). 명단을 참고만 하는 확인 작업에는 취합 config를 읽거나 만들지 않는다. |
| 업무현황에 보고를 명시적으로 요청 | [납품 스킬의 콘솔 전용 경로](../hwpx-workspace-delivery/SKILL.md#console-communication-and-requested-artifacts). 보고만 갱신하며 문서 접수·저장·검토 단계는 유지한다. |

한글 읽기/편집은 설치된 HWPX 스킬과 [Windows 실행 경로](../hwpx-runtime/SKILL.md)를 사용한다. 다른 형식에는 그 형식의 도구를 쓴다. 참조 파일 때문에 요청한 결과 형식을 바꾸거나 추가 산출물을 만들지 않는다.

학교 작업공간에서는 `.agent/shared/evidence-fill-check/SKILL.md`가 정본이다. 개인용 사본의 상대 링크도 이 정본 위치를 기준으로 해석한다. 다른 환경에서는 실제 존재하는 도구를 사용하며 학교 전용 경로를 강제하지 않는다. 미러 보관만으로 개인 스킬 설치/갱신이 완료된 것은 아니다.

## 항목 연결과 근거

- 과목·학년·학기·프로그램·단위 문맥으로 항목을 연결한다. 같은 양식은 머리글·행 이름·구조 확인 후 매핑을 재사용하고, 다른 양식은 별도로 매핑한다. 셀 좌표가 의미 판단을 대신하지 않는다.
- 한 파일에 여러 과목의 값이 있을 수 있다. 실제 제출값과 양식의 예시/기본값을 구분하고 파일 수를 과목 수로 세지 않는다.
- 원문과 정규화 값을 구분한다. 공란, 명시적 0, 해당 없음, 자료 없음은 별도 상태다. 단위 변환은 근거·식을 남기고, 약칭은 문맥으로 확인된 대응만 사용한다.
- 적용 시기·단위·대상이 맞고 충돌이 없는 값만 반영한다. 개요와 세부 합계의 충돌을 다수결이나 합계 일치로 해결하지 않는다. 불확실한 항목은 기존 값을 유지하고 이유를 남기며 나머지는 진행한다.
- 사용자가 정한 충돌 해결 기준은 해당 항목에 기록·적용한다. 이미 한 결정을 재승인받거나 다른 항목에 확대하지 않는다.

작업 로컬 기록에 `대상 위치 / 연결 항목 / 현재 값 / 근거 값·단위 / 근거 파일·위치 / 판정·이유`를 남긴다. 실행기 기록이 이를 담으면 별도 보고서/config를 중복 생성하지 않는다. 위치는 표·행·셀, 시트·셀, 쪽·문단처럼 다시 찾을 수 있어야 한다. 개인정보는 로컬 자료에만 둔다.

같은 양식은 차이 셀과 실제 제출 항목을, 비정형 자료는 관련 절·머리글과 필요한 문맥을 읽는다. 누락이나 대응 불확실성이 관찰될 때 범위를 넓힌다. 줄바꿈·병합 셀을 생략하는 추출기라면 관련 원문을 확인한다. 같은 추출 결과끼리의 일치가 완전성을 증명하지 않는다.

## 수정할 때만

확인에서 수정으로 전환하면 현재 파일 해시를 다시 확인하고 변경된 자료에 의존하는 항목·합계·충돌 판단을 갱신한다. 수정용 접수 후 변경 전후 값/위치(diff)를 확정해 지원 도구의 dry-run → commit → 출력 검증 → 요청된 게시를 수행한다. 차이가 없으면 다시 저장하지 않는다.

내용 변경과 표 구조 변경을 구분한다. 구조를 바꾸려면 도구와 게시 검사가 그 변경을 지원하는지 확인한다. 이는 기술 확인이며 새 사용자 승인 단계가 아니다. 지원하지 않으면 수정 사본·차이 근거와 미지원 연산/검사를 남기고 독립 작업을 계속한다. 다른 작업의 영수증이나 재승인으로 기술적 차단을 해결하지 않는다.

편집용 열기가 open-safety에서 실패해도 지원되는 읽기 전용 추출로 사실 대조는 진행할 수 있다. 읽기 성공은 편집 가능성/무결성 통과가 아니다. 수정 복구는 파일 형식별 지원 절차로 별도 사본에서 원본·무관한 내용 보존과 패키지/열기 안전성을 확인한다. 지원 복구가 없거나 검사가 실패하면 편집을 강행하지 않는다. HWPX ZIP 구성원이나 원시 OWPML XML을 직접 쓰지 않는다.

확정 변경을 일괄 반영하고 변경 셀·비변경 영역, 관련 누락·중복·합계와 파일 무결성을 확인한다. 서식 조정/외관 검사는 요청 범위에 따른다. 입력·대상 해시, 항목 매핑과 관련 도구 버전이 일치하는 성공 기록은 재사용한다. 잠금/실패 시 저장 여부를 확인한 뒤 재시도하며 도구 탐색을 처음부터 반복하지 않는다.

## 완료

확인 작업은 요청 항목별 판정·근거·읽기 제한을 보고하면 끝난다. 수정은 변경 범위와 출력 무결성 및 요청된 게시 단계까지 확인한다. [점검 경로](../CHECK-WORKFLOW.md)에 따라 실제 검사와 미확정 사항, 결과 위치를 보고한다. 콘솔 보고가 요청되지 않은 확인 작업은 채팅으로 끝낸다. 학교 산출물에는 기존 권위·출처 보존·open-safety·게시 게이트가 적용된다.

Review/Final은 요청 내용의 완료이며 공식 승인·제출·운영 완료가 아니다. 콘솔 보고, 읽기 대조, 편집/게시의 검증 수준을 구분한다. 반복 사용에서 관찰한 병목만 개선하며 의미 판단은 스킬에, 반복 연산은 기존 실행기에 둔다. 문서 작업 중 게시 정책을 낮추지 않는다.
