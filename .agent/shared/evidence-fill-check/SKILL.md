# 자료 근거 기반 채움·대조

현재 사용자 파일과 이미 정한 기준을 사용한다. 제공 자료로 충분하면 이전 연도까지 검색하지 않는다. 학교 작업공간의 정본은 이 문서이며 개인 스킬 사본을 자동 설치·갱신하지 않는다.

| 요청 | 적용 경로 |
|---|---|
| 값 확인만 | 필요한 항목을 읽고 근거·판정을 채팅으로 보고. 파일·접수·현재 등록 변경 없음 |
| 근거에 따른 수정 | [문서 처리](../../../.agents/skills/hwpx-workspace-delivery/SKILL.md)의 접수·초안 게시 경로와 해당 형식의 편집 도구 |
| 같은 한글 표의 학생 명단 취합 | [명단 취합 실행기](../collect-hwpx-rosters/SKILL.md) |
| 업무현황 HTML 보고 요청 | [콘솔 보고](../../../.agents/skills/hwpx-workspace-delivery/references/console-report.md) |

한글은 설치된 HWPX 스킬과 [Windows 실행 경로](../hwpx-runtime/SKILL.md)를 사용한다. 참조 파일 때문에 요청 결과의 형식을 바꾸거나 추가 보고서를 만들지 않는다.

## 근거를 연결하고 초안 저장

기존 초안·양식과 필요한 근거부터 읽는다. 과목·학년·학기·대상·단위로 항목을 연결하고, 같은 양식은 머리글·행 이름을 확인한 뒤 매핑을 재사용한다. 병합 표는 라벨과 값 입력칸을 구분한다. 셀 좌표나 파일 수만으로 의미·과목 수를 판단하지 않는다.

실제 제출값과 예시·기본값을 구분한다. 공란·0·해당 없음·자료 없음은 서로 다른 상태다. 단위 변환과 약칭은 확인된 근거만 사용한다. 충돌이 있으면 해당 항목의 기존 실제 값을 보존하고 미확정으로 보고하며 나머지는 채운다. 예시값을 확정값으로 남기지 않는다. 사용자가 정한 해결 기준과 자료의 기준일을 재사용한다. 합성 시나리오는 그 시나리오의 근거를 따른다.

기본은 `Start-HwpxWork.ps1 -DraftFirst`로 접수하여 작성 가능한 부분을 먼저 저장하고 Review 초안을 게시하는 경로다. 이 경로의 `content` 확인은 실제 채운 부분의 핵심값·반복값 표본, 관련 합계와 요청 밖 내용 보존을 확인한 범위다. 전항목 `sourceRef`, 필수 프로필 바인딩, 항목별 판정표나 별도 검증보고를 초안 저장의 선행 조건으로 만들지 않는다. 필요한 근거 위치는 기존 편집 계획에 짧게 남겨 후속 보완에 재사용한다.

`업무프로필.json`이 있으면 필요한 매핑의 참고로 읽되 초안에 모든 검사를 자동 강제하지 않는다. 프로필과 원본이 다르거나 대응이 불분명하면 그 항목만 미확정으로 남긴다. 추가 읽기는 발견한 누락·충돌을 해결하는 범위로 좁힌다.

## 편집과 확인

지원 도구의 dry-run·적용·저장 절차를 따른다. 수정 전 현재 파일 해시를 확인하고 변경된 근거에 의존하는 항목만 갱신한다. 차이가 없으면 다시 저장하지 않는다. 원본·기존 서식·요청 밖 내용은 보존한다. 저장된 출력에서 실제 채운 핵심값과 예시·옛 날짜가 남을 우려가 있는 위치를 표본 확인하고, 해당 형식의 무결성·열기 안전 검사는 유지한다. 표본 확인을 전항목 완료로 보고하지 않는다.

편집용 열기가 open-safety에서 실패하면 지원되는 읽기 전용 대조는 가능하지만 편집을 강행하지 않는다. 복구는 지원 절차로 별도 사본에서 수행하고 원본·패키지·열기 안전성을 확인한다. HWPX ZIP 구성원이나 원시 OWPML XML을 직접 쓰지 않는다. 지원하지 않는 구조 변경은 미완료로 남기고 독립 작업을 계속한다.

입력·출력·도구 버전이 같은 성공 기록은 재사용한다. 잠금·실패 시 저장 여부를 먼저 확인하고 해당 부분만 재시도한다. 초안 저장 후 한 차례 핵심 확인으로 끝내고, 완성도 향상을 위한 자동 수정 반복은 하지 않는다. 명백한 오입력이나 파일 손상은 바로잡되 세부문안·미확정 항목은 다음 할 일로 제안한다. 결과 위치와 확인한 범위를 짧게 보고하고, 보완 제안은 중요한 순서로 최대 3개만 `남은 항목 — 필요한 자료 또는 다음 작업` 형태로 채팅에 쓴다. 사용자가 선택한 뒤 해당 부분만 이어서 수정한다. Review는 검토용 초안이며 공식 승인·제출 완료가 아니다.

## 명시적으로 요청한 엄격검증

전항목 대조·필수 프로필 검증을 요청한 때만 `-RequireContentValidation`과 [저장본 내용 계약](content-contract.md)을 사용한다. 이 경로에서는 항목별 근거·출력 대조와 등록된 필수 검사를 완료하며, 실패를 숨기거나 기대값을 바꿔 통과시키지 않는다. 기존 엄격검증 job을 `-DraftFirst`로 낮추지 않는다. 초안 작업을 별도로 시작해야 하면 새 `JobSlug`로 접수하고 기존 기록을 보존한다.
